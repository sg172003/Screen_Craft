# Source #04 — llms.txt useless: log analysis on 50+ sites

- **URL:** https://www.rankit.fr/fichier-llms-txt-inutile
- **Author:** Frédéric Jézégou (Rankit.fr)
- **Date:** 2026-03-27
- **Type:** Empirical log analysis + cited authority quote

## Triage

🟢 **Universal — settles the llms.txt debate**

- Server logs of **50+ sites** with `llms.txt` accessible (linked from home, not blocked, HTTP 200). **Zero LLM crawlers** read the file. Only Google crawled it as a normal asset.
- **John Mueller (Google)** confirmed publicly: no LLM consumes the file.
- No major LLM provider (OpenAI, Google, Anthropic, Perplexity, Mistral, Common Crawl) supports it as of 2026.
- Yoast and RankMath auto-generate it by default. Should be disabled — it's marketing fluff, no measurable benefit.

🟡 **Context-specific** — none.

🟠 **Hard-mode-gated** — none.

🔴 **Over-claimed considerations** — none. Methodology is straightforward (log analysis), claim is conservative ("zero observed", not "will never happen").

## What we integrate

- `skills/geo-llmstxt/SKILL.md` reframed: the file is a **cosmetic/low-confidence signal**. The toolkit reports its presence/absence as informational, but never recommends it as a quick win or critical fix.
- New audit recommendation pattern: if `llms.txt` exists AND auto-generated by Yoast/RankMath, suggest disabling to stop polluting Google's crawl budget.
- This source consolidates `tasks/lessons.md` entry "Don't promote unproven GEO signals as critical".

## What we explicitly do NOT integrate

- A blanket "delete your llms.txt" recommendation. The file is harmless if static. Just stop generating/maintaining it as if it were a ranking signal.
